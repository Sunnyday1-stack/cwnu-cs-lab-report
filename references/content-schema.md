# content.json 规范

`report_tool.py build` / `fill` 读取一个 UTF-8 JSON 文件。顶层结构：

```json
{
  "format": {},
  "meta": {},
  "layout": {},
  "sections": []
}
```

`build` 会用一条命令完成填充、排版修补、另存和预览；`fill` 只做填充（加 `--layout` 才应用 layout）。

## format（可选）

覆盖默认排版，单位：磅。

```json
{
  "body_font": "宋体",
  "latin_font": "Times New Roman",
  "heading_font": "黑体",
  "body_size": 12,
  "heading_size": 12,
  "code_font": "Consolas",
  "code_size": 9,
  "table_size": 10.5,
  "caption_size": 10.5,
  "line_spacing": 1.5
}
```

默认正文小四（12 磅）、1.5 倍行距、首行缩进 2 字符；代码按最长行自动降到 9/8.5/8/7.5/7 磅。

## meta（可选）

只填表格中的字段，例如课程名称、实验名称。键名可用模板原文或常见别名。

```json
{
  "课程名称": "计算机操作系统",
  "实验名称": "实验一 非抢占式短进程优先调度算法的模拟"
}
```

页眉段落中的“报告人姓名、学号、指导教师、日期、年级、班级”需要再加命令行参数 `--meta-paragraphs` 才会替换。未传该参数时会在结果里提示。

不要填“成绩”“教师评语”。

## layout（可选，build 默认应用）

排版修补，在一次 Word 会话内完成，替代以前手写 fix 脚本。

```json
{
  "layout": {
    "no_split": "nested",
    "header_repeat": "off",
    "clear_row_heights": [1],
    "center_captions": ["表 1 测试用例", "表 2 测试用例"]
  }
}
```

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `no_split` | `off` / `nested`（默认）/ `top` / `all` | 行内禁止跨页断行。**不要对顶层大表格用**：单元格内容超过一页时 Word 会裁掉放不下的正文 |
| `header_repeat` | `off`（默认）/ `top` / `nested` / `all` | 首行重复为表头。Word 对嵌套表格不生效，见下方“Word 限制” |
| `clear_row_heights` | 表格序号数组，如 `[1]` | 把指定顶层表格的行高规则改为“自动”，消除模板预留行高造成的大片空白 |
| `center_captions` | 字符串数组 | 找到以这些文字开头的段落并居中，用于模板原有的图注/表注 |

**Word 限制（不要浪费轮次去试）：**

1. 嵌套在单元格里的表格无法跨页重复表头（`HeadingFormat` 被忽略）。数据超过 3 行就可能跨页，应主动拆成多个 3 行以内的小表，每张表自带表头。
2. 表格单元格内的分页符/`PageBreakBefore` 会被忽略，靠插分页符控制表格内部排版无效，只能靠拆表、增减段落调整。
3. 给高过一页的行设置“禁止跨页断行”会把内容直接裁掉，页数骤减但正文丢失；只能对嵌套小表使用。

## sections（必填）

```json
{
  "label": "实验内容",
  "row": 6,
  "mode": "fill",
  "blocks": []
}
```

- `label`：模板中的栏目名，可用常见别名（见下）。
- `row`：可选。同名栏目出现多次时指定行号，例如“实验内容或上机调试程序”连续两行。
- `mode`：
  - `fill`（默认）：仅当栏目为空白时写入，已有内容则跳过。
  - `replace`：清空栏目后重写。只在用户明确要求覆盖时使用。
  - `append`：保留已有内容，在末尾追加。

脚本结果会逐条返回 `filled` / `skipped` / `failed` 及原因，必须检查。**未知栏目名会在启动 Word 之前直接报错退出**，错误信息里列出全部可用栏目名。

### 栏目别名

| 标准名 | 可识别的常见写法 |
| --- | --- |
| 实验目的 | 实验目的、实验目的和要求、目的与要求 |
| 实验原理 | 实验原理、基本原理、算法原理 |
| 实验环境 | 实验仪器和器材、实验设备、实验环境、软硬件环境 |
| 实验内容 | 实验内容或上机调试程序、实验内容、实验步骤、实验过程 |
| 问题及解决 | 问题及解决办法、问题及解决、遇到的问题及解决办法、问题与解决 |
| 运行结果 | 运行结果截图、实验结果、实验结果与分析、测试结果 |
| 心得体会 | 实验心得体会、实验心得、心得体会、实验总结、总结与体会 |

标准名本身一定可识别，别名表只是扩充写法。

## blocks 块类型

### paragraph 正文

```json
{"type": "paragraph", "text": "第一段。\n第二段会分成两个段落。", "indent": true}
```

`indent` 默认 `true`（首行缩进 2 字符）。正文自动两端对齐；`align` 可选 `left` / `center` / `justify`。
`keep_with_next: true` 让该段与其后内容保持在同一页（适合放在表格前的引导句）。

### heading 小标题

```json
{"type": "heading", "text": "一、测试用例设计"}
```

黑体、加粗、小四、无首行缩进，默认与其后内容同页。

### caption 图表注

```json
{"type": "caption", "text": "表 1 测试用例（1～3）"}
```

居中、五号、单倍行距。放在表格后面时不要加 `keep_with_next`；放在表格前面时加 `"keep_with_next": true`，避免图注单独留在页尾。

### list 列表

```json
{"type": "list", "style": "paren", "items": ["用例一……", "用例二……"]}
```

`style`：`paren`（默认，输出“（1）”）、`dot`（“1.”）、`circle`（“①”）、`dash`（“-”）。

### code 代码

```json
{"type": "code", "text": "for (int i = 0; i < n; i++) {\n    sum += a[i];\n}"}
```

- 每个换行符对应 Word 中一个段落，单倍行距。
- Tab 自动替换为 4 个空格，保留原有缩进。
- 浅灰底纹 + 左侧竖线。
- 只贴关键代码，不要把整个工程文件粘进去；报告里的代码应与实际运行的版本一致。

### table 表格

```json
{
  "type": "table",
  "headers": ["输入", "预期顺序", "实际顺序", "结果"],
  "rows": [
    ["P1(0,2)、P2(3,4)", "P1→P2", "P1→P2", "一致"]
  ],
  "widths": [5, 3.2, 3.2, 2],
  "font_size": 10.5,
  "header_bold": true,
  "no_split": true,
  "header_repeat": true
}
```

- `widths` 单位厘米，可省略（平均分配）。
- 表头加粗居中，全表带边框；行内默认不跨页断行。
- 表格作为嵌套表格插入栏目单元格。**数据超过 3 行就拆表**：Word 无法让嵌套表格的表头跨页重复，超长表格续页后没有表头。拆表时每张表后面紧跟一个 `caption` 块（表 1、表 2……）。

### image 图片

```json
{"type": "image", "path": "D:/实验数据/截图1.png", "width_cm": 12, "caption": "图 1 调度运行结果"}
```

- 建议使用绝对路径。
- 默认宽度 12 cm，图片居中，图注自动居中放在下方。
- 只插入用户真实提供的截图，不要用生成的假截图冒充运行结果。

### placeholder 截图占位

```json
{"type": "placeholder", "text": "【此处粘贴运行结果截图】", "note": "包含菜单、输入、调度输出三张"}
```

- 生成灰色边框占位区，`note` 用软换行写在同一段内。
- 有明确截图要求时，把要截的画面写进 `text` 或 `note`。

## 完整示例

```json
{
  "format": {"body_size": 12, "code_size": 9},
  "meta": {"课程名称": "计算机操作系统"},
  "sections": [
    {
      "label": "实验内容",
      "row": 6,
      "mode": "replace",
      "blocks": [
        {"type": "heading", "text": "附：测试用例与验证过程"},
        {"type": "paragraph", "text": "为验证调度结果，构造了正常、CPU 空闲和同时到达三类用例。"},
        {"type": "table",
         "headers": ["输入", "预期顺序", "实际顺序", "结果"],
         "rows": [["P1(0,2)、P2(3,4)", "P1→P2", "P1→P2", "一致"]],
         "widths": [5.2, 3.2, 3.2, 2.2]},
        {"type": "code", "text": "while (completed < n) {\n    /* 选择已到达的最短进程 */\n}"},
        {"type": "placeholder", "text": "【此处粘贴三个用例的运行截图】", "note": "截图后删除本行"}
      ]
    },
    {
      "label": "问题及解决办法",
      "mode": "fill",
      "blocks": [
        {"type": "paragraph", "text": "问题：当前时刻无进程到达时循环卡住。原因：未处理 CPU 空闲。解决：把 current_time 跳到最早到达时刻后重新选择。"}
      ]
    },
    {
      "label": "心得体会",
      "mode": "fill",
      "blocks": [
        {"type": "paragraph", "text": "500—800 字，必须引用本次实验的具体代码、参数或调试过程。"}
      ]
    }
  ]
}
```

## 填充行为与注意事项

1. 脚本按“表格 + 行 + 栏目名”定位单元格，前面栏目写长后不会影响后面的定位。
2. 默认不覆盖已有内容；想补写在现有内容后面用 `append`。
3. 重复填充同一成品会因栏目非空而跳过。需要重排时，从原始模板重新填充到新文件。
4. 图片和代码过多会把栏目撑到多页，先看 `build` 返回的预览页，再精简内容或缩小图片。
5. 不要删除模板中的空行、合并单元格或调整表格结构。
6. 返回结果中的 `warnings`、`placeholders_left`（成品里剩余的“【”数量）必须逐条处理，不能忽略。
7. 调整排版后从**原始模板**重新 `build`，不要在成品上二次填充。
