# 实验报告写作指南

按栏目、按实验类型给出具体写法。所有内容必须来自本次实验的材料与真实运行结果，本文只规定“怎么写”，不提供可套用的范文。

## 总体语言风格

- 用陈述句写“做了什么、怎么做的、结果是什么”，不用第一人称抒情。
- 术语跟教材和指导书保持一致，同一概念不换说法（如“周转时间”不要一会儿写成“响应时间”）。
- 数字带单位，算法写清输入规模与参数（如“进程数 n=5，时间片 q=2”）。
- 一段只讲一件事。步骤用编号，结果用表格，代码用代码块。
- 不写“非常重要”“意义重大”“极大地提高了”这类评价性空话。

**反例 → 正例**

| 反例 | 正例 |
| --- | --- |
| 本实验实现了进程调度算法，效果良好。 | 采用非抢占式 SJF，按到达时间顺序扫描就绪队列，5 个进程的平均周转时间为 6.8，平均带权周转时间为 1.94。 |
| 通过本次实验我学到了很多知识。 | 调试中发现按服务时间排序后未同步更新完成时间，导致第 3 个进程的周转时间偏大 2 个时间单位，改为在每次选中进程后立即写回 finish 数组后结果与手工推演一致。 |

## 各栏目写法

### 实验目的

3～5 条，动词开头，写成本次实验能达到的具体能力，不抄课程大纲。

- 写：理解非抢占式短进程优先调度的判定条件；掌握就绪队列按服务时间排序的实现方法；会用周转时间和带权周转时间评价调度效果。
- 不写：培养动手能力、提高综合素质。

### 实验原理

只写本实验用到的原理，篇幅 1～3 段或几个要点：

- 核心定义与公式：如周转时间 = 完成时间 − 到达时间，带权周转时间 = 周转时间 / 服务时间。
- 关键规则与边界：抢占/非抢占、到达时间相同如何排序、空闲期怎么处理。
- 数据结构与流程：就绪队列、进程控制块字段、主循环的每一步。
- 有公式时写清各符号含义；有推导时给出中间步骤，不跳步。

不整段复制教材，不写与本实验无关的算法史。

### 实验环境

按模板已有的粒度写，通常一行即可：

- 操作系统及版本、编译器/IDE 及版本、语言标准、仿真软件及版本、数据库版本。
- 例：Windows 11 + Dev-C++ 5.11（TDM-GCC 4.9.2，C99）。
- 只有确实影响结果时才写硬件配置（如并行、GPU、内存上限）。

### 实验内容与步骤

这是报告主体，按“做什么 → 怎么做 → 得到什么”组织：

1. 先用一两句说明任务与输入输出约定。
2. 再给关键步骤：数据结构定义 → 核心函数 → 主流程，配代码块。
3. 代码只贴实现本题的部分，删掉无关的菜单、测试脚手架；每段代码前一句话说明它在整体中的位置。
4. 步骤编号与代码顺序一致，读者能按编号复现。
5. 涉及配置（网络、数据库、环境变量）时给出完整可粘贴的命令或配置片段，并注明在哪个设备/目录下执行。

代码块要求：能被独立看懂，关键变量有含义，不贴大段注释掉的旧代码。

### 测试与运行结果

- 测试用例至少 3 组：1 组典型、1 组边界（空输入/单元素/同时到达/极值/异常参数）、1 组规模稍大的。
- 每组写清：输入、预期输出（先手工推演）、实际输出、是否一致。
- 用 `table` 块汇总，列建议为：编号 / 输入 / 预期结果 / 实际结果 / 结论。
- 有截图时在表后用 `image` 块并加图注，图注写“图 3 进程数 n=5 时的调度输出”，不写“运行截图”。
- 无法实际运行时，只写预期结果并注明“未实际运行”，不得写成已运行。

### 问题及解决办法

只写真实发生的问题。没有就写“无”，不要编。

每条按四段写，2～4 条即可：

1. 现象：什么操作、看到什么报错或异常结果（贴关键报错行）。
2. 定位：怎么缩小范围到具体函数/语句/配置。
3. 原因：一句话说清根因。
4. 解决：改了什么，改后结果如何。

例：编译报 `undefined reference to 'sortByBurst'` → 检查发现函数定义写在 `main` 之后且未声明 → 在文件头部补函数原型 → 重新编译通过。

不要写“上网查资料后解决了”这种没有信息量的过程。

### 心得体会

500～800 字，紧扣本次实验，用下面的四段式，不必分段标题：

1. **做了什么**：一句话概括实现思路与自己动手的部分（1～2 句）。
2. **具体收获 2～3 点**：每点必须落到本次实验的代码、参数、公式或调试细节。例如“把 ready 队列改成按 burst 升序插入后，才理解非抢占式与抢占式的差别不在排序，而在是否允许中断当前进程”。
3. **验证与对比**：说明自己如何确认结果正确（手工推演、与另一种算法对比、改变参数观察趋势），给出具体数字。
4. **不足与改进**：指出一个真实短板和可执行的改法，如“当前用 O(n²) 扫描选最短进程，进程数增大后可改为小根堆”。

禁止出现的句式：

- “通过本次实验，我学到了很多/受益匪浅/感受颇深”。
- “让我对……有了更深刻的认识”单独成段而无具体内容。
- 把实验目的、原理再复述一遍充字数。
- 与本次实验无关的感悟（团队合作、人生道理）。

## 按实验类型的差异

| 类型 | 重点写 | 特别要求 |
| --- | --- | --- |
| 编程/算法（OS、数据结构、Java、C/C++） | 数据结构、核心算法、复杂度、测试用例与输出 | 代码可编译；给出至少一组手工推演；说明时间/空间复杂度 |
| 网络仿真（eNSP、Packet Tracer） | 拓扑图、设备型号、接口与 IP 规划、关键配置、连通性验证 | 配置命令按设备分段、可直接粘贴；用 ping/tracert/display 命令的输出作为结果 |
| 数据库 | 表结构、约束、索引、建表与查询 SQL、执行结果 | 给出测试数据；复杂查询附执行计划或耗时对比；说明事务与隔离级别（如涉及） |
| 硬件/组成原理 | 器件清单、连线/引脚、真值表或波形、故障现象与排查 | 用表格列引脚与电平；波形用图或时序表描述；说明测量工具 |
| 信息安全 | 环境与靶机、攻击/防护步骤、关键 payload、检测与修复 | 只写授权范围内的实验；命令与输出对应；给出修复建议与验证方式 |

## 常见扣分点

- 栏目留空或只写“略”“同上”。
- 实验目的与实验内容不对应，明显是模板套话。
- 只贴代码不解释，或代码无法编译、与输出对不上。
- 运行结果没有截图或截图看不清关键输出；截图含他人姓名、桌面隐私信息。
- 测试只有一组，且没有边界情况。
- 问题及解决办法写“无”，但结果明显经过修改或与代码不符。
- 心得通篇空话，或大段与实验无关。
- 破坏模板：改动页眉、删除原有栏目、字号字体不统一、表格错位。
- 直接复制网络范文，术语和课程教材不一致。
